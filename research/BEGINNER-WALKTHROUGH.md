# v2 新手视角走读

日期：2026-10-20。审阅者：独立 agent `v2_beginner_walkthrough`，未参与产品制作，仅负责本记录。

这是 **agent 模拟的新手走读，不等于真人可读性测试**。设定读者为使用过大模型产品、具备基本编程常识，但不了解 Transformer 推理内部机制的工程师。模拟审阅者本身具有技术背景，因此对真实读者的记忆负担、阅读速度和误解概率的判断有上限。仍建议邀请 2–3 位真实新手完成路线及自测。

## 方法与范围

- 通过 Playwright 启动实际 Chrome，读取渲染后的正文、操作页面并查看截图；内容判断未通过阅读产品源码获得。
- 入口：`http://127.0.0.1:5173/?lang=zh&path=beginner`；补读 `lang=en`。
- 仅按新手路线阅读：`basics → journey → system → scheduling → decode-lab → experts → recipe`。未把进阶章节内容当作读懂本路线的前提。
- 中文逐章精读；英文逐章补读，重点检查同一概念和术语缺口是否也存在。Chrome 的 1280 × 900、375 × 900 两种视口均检查，四组均未出现页面级横向溢出或 JavaScript 异常。
- 本记录不替代主验收的 WebKit、深浅色、axe 或背景来源审核。

## 自测三问

在展开答案前，按正文内容给出以下答案，再与展开答案对照：

| 问题 | 模拟读者答案 | 对照结果 |
|---|---|---|
| KV 缓存省掉的是什么？ | 省去旧位置键和值的重复计算；普通全注意力仍会读取相关历史 KV，并非所有历史处理都消失。 | 正确，正文和图示支持。 |
| 为什么输入处理与生成可以分开部署？ | 两阶段工作形态及常见资源瓶颈不同，可以分别配置资源并减少干扰；同时需要支付状态传输与协调成本。 | 正确，正文和展开答案一致。 |
| 热门专家拥堵，换成任意空闲专家可以吗？ | 不行，不同逻辑专家权重不同；同一专家的副本才可承担相同专家的工作。 | 正确，MoE 小节已给出必要依据。 |

## 导航与交互复走

- URL 中 `path=beginner` 正确选中新手按钮，路线顺序符合计划。
- 实际逐次点击章节“下一章”，地址依次进入 `#journey`、`#system`、`#scheduling`、`#decode-lab`、`#experts`、`#recipe`。Recipe 的路线末端为“查阅术语表”，没有强制进入路由或 YOCO。
- 首轮检查各章前后链接，两方向均指向路线相邻站点。
- 中英 × 1280/375 均抽查术语交互：聚焦 tokenizer 术语打开浮层，Escape 关闭，点击再次打开。未要求读者只能使用鼠标悬停。
- 移动端图示置于独立横向滚动区域，而非挤压文字或扩大整页。EPLB 图区域可聚焦，并通过键盘右箭头移动，复走记录显示 `scrollLeft=40`、可滚动距离 `321`。
- 桌面 EPLB 图实际截图可辨认左侧热点、同权重副本、右侧均衡负载；没有观察到该图中文字与连线重叠。移动端需横向查看整图，页面有提示。
- KV 参数说明、输入滑块与结果在 375 宽度可读。DSpark 教学结果和官方报告位于不同区块，有明确示意标签。
